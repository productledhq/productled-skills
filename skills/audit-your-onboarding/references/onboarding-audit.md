# Template: Onboarding Audit / Bowling Alley Map (Component 5)

The deliverable is a step-by-step map with verdicts, not commentary. Baseline: 40–60% of signups never return; companies that run this typically kill 30–40% of steps and make value 2–3× easier to reach. Snappa: +20% MRR in one week.

## 1. Straight line map (Visit → First Strike)

Get every step from the user: every screen, form, and "OK" button counts. Map to First Strike first (that's where 40–60% drop), KUI and Upgrade on later passes.

| # | Step | Label | Verdict |
|---|---|---|---|
| 1 | … | 🟢 necessary / 🟡 delay / 🔴 remove | why |

Labeling rules: 🟢 = account literally can't work without it. 🔴 = nobody needs it now (profile color, nickname). 🟡 = needed eventually, not now. This is the hardest call; when in doubt, delay it. Target: kill 30–40%, delay ~20%.

## 2. Profiling questions (only additions allowed)

Steps may be ADDED only if they personalize the journey. Two legitimate types: identifies ideal vs. non-ideal user; catapults user to the right value path. (Monday.com: 5 questions → right template. ChannelReply: 2.) Propose the exact questions and what each answer changes downstream.

## 3. Product bumpers (deploy only at observed drop-off points)

Welcome message · product tour · progress bar · checklist (pre-fill an item) · tooltips (no tooltip soup) · empty states. For each proposed bumper: which drop-off it addresses, and what it says (write the actual microcopy).

## 4. Conversational bumpers (for users who never come back in-app)

Pick from the Care Continuum (hands-off → hands-on): external messaging · knowledge base · in-app chat · community · training · specialists. Match hands-on level to LTV: no specialists for $10/mo customers. Early-stage default: go MORE hands-on than sustainable to learn, then reverse-engineer the scalable version.

## 5. If they've never done this: prescribe VIP onboarding instead

White-glove every signup for 2–4 weeks (welcome email, onboarding call, manual setup, trial extension). Find the winning pattern, then turn it into scalable bumpers. Do the unscalable to learn; then reverse-engineer.

## Output order

Map table → kill list (steps to remove this week) → profiling questions → bumper plan with copy → measurement plan (which True North metric proves it worked).
