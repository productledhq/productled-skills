# Price With Value Metrics

If free users love you and never upgrade, your pricing isn't too high. It's measuring the wrong thing. The value metric is what you charge for, and it must grow as the user's value grows. Get that right and upgrades become a natural step instead of a negotiation.

## How to work

1. **Get the inputs**: current pricing and plans, what the ideal user's success looks like (their endgame), which usage dimension grows as users succeed, upgrade rate, and where users stall.
2. **Read `references/Value Metric.md`** and find their value metric: it must (a) align with the value the user receives, (b) grow as the user succeeds, and (c) be easy to understand. Test candidates against all three. Seats often fail (a), and a metric users can't predict fails (c).
3. **Read `references/Value Ladder Framework.md`** and structure the ladder: each rung solves the problem the previous rung created. A user hitting a plan limit should be *winning*, not annoyed: the limit lands exactly where their success makes the next rung obviously worth it.
4. **Check the free-to-paid line**: the free tier must deliver real value AND naturally run into the value metric as the user grows. If upgrading requires a sales conversation for a self-serve product, the ladder is broken.

## Output format

1. **The value metric**: one committed recommendation with the three-test evidence.
2. **The ladder**: each tier: who it's for, what it unlocks, where the limit sits and why that's the moment of highest willingness to pay.
3. **What to change first**: the single pricing move with the highest expected impact, and the metric to watch (KUI → upgrade rate).
4. **What would change your mind**: the evidence that would point to a different metric.
